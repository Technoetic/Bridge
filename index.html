🎨 도형 렌더링 시스템

Bridge 패턴을 활용한 추상화와 구현의 분리

브리지 패턴의 핵심:
도형(추상화)과 렌더링 방식(구현)을 독립적으로 분리합니다. 새로운 도형을 추가해도 렌더링 방식을 수정할 필요가 없고, 새로운 렌더링 방식을 추가해도 도형 코드를 수정할 필요가 없습니다. 이 둘은 브리지로 연결되어 자유롭게 조합됩니다.

📚 Bridge 패턴 설명

패턴 개요

Bridge 패턴은 추상화와 구현을 분리하여 독립적으로 변경할 수 있도록 하는 구조 패턴입니다. 상속 대신 조합을 사용하여 더 유연한 설계를 가능하게 합니다.

핵심 구성요소

• Abstraction (추상화): 고수준 제어 로직 (도형)
• Implementation (구현): 저수준 플랫폼별 구현 (렌더러)
• Bridge: 추상화가 구현을 참조하는 연결고리

적용 사례

• 플랫폼 독립적인 UI 프레임워크
• 데이터베이스 드라이버
• 디바이스 드라이버
• 다양한 렌더링 엔진 지원 ← 현재 예제

// 추상화 (Abstraction) class Shape { constructor(renderer) { this.renderer = renderer; // Bridge } draw() { throw new Error('Must implement'); } } // 구현 (Implementation) class Renderer { renderCircle() { throw new Error('Must implement'); } renderSquare() { throw new Error('Must implement'); } } // 구체 추상화 class Circle extends Shape { draw() { this.renderer.renderCircle(); // 구현 위임 } } // 구체 구현 class CanvasRenderer extends Renderer { renderCircle() { // Canvas API로 원 그리기 } }
